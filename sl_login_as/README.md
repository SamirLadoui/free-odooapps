# Log In As Another User

> See What A User Sees, With A Reason And A Record That Cannot Be Erased

Somebody reports that a button is missing, and the only way to see what they see is to be them. The usual answer is to reset their password, which locks them out and tells you nothing afterwards. This opens a session as that user instead, and writes down that it happened.

## Features

- **Containment, Not Seniority** - You may take an account only if you already hold every right it has. A support account that could become somebody more powerful has effectively granted itself that power - which would make this a way around the access rights the database already has, rather than a support tool.
- **The Reason Is Asked First** - Before the session starts, not remembered afterwards. It is the only part of the record that says what the session was for.
- **The Record Cannot Be Tidied Away** - Who did it, whose account, when and why - and the entry cannot be edited or deleted by anybody, including whoever created it. A log an administrator can clean up is not a log.
- **The Address Is Not A Way Round It** - The page that hands over the session checks the same rule again and refuses unless a reason was recorded for that pair moments before, so pasting the link does not skip the question.
- **Nobody Is Locked Out** - The other person's password is untouched and they are never signed out. They need not know, and need not be available.

## Getting Started

1. Install the module.
2. Open Settings ► Users, pick a user, and press Log In As This User.
3. Give the reason and continue - the session is now theirs.
4. Sign out and back in to return to your own account.
5. Every use is listed under Settings ► Logged In As.

## Good To Know

- Only a user with the Access Rights administration group may do this at all.
- Taking your own account is refused, as is taking one with rights you do not have.
- The entry records the time it happened, so a session can be placed against a support ticket afterwards.
